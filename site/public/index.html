Always-on Organized Audio Transcript System

Record both sides of the call. Keep the files.

onoats captures your microphone (me) and system audio (them) as separate streams, transcribes each, and writes plain JSONL and Markdown. No database, no account, nothing leaves your machine unless you point it at a hosted STT.

Install View on GitHub

Two channels, never mixed

Each source has its own socket, its own speech-to-text session and its own tag. Who said what is known from the wiring, not guessed from the audio.

me

Your microphone

Captured from your input device and transcribed on its own branch.

them

System audio

Everyone else on the call, via a native Core Audio tap on macOS 14.4+. No virtual loopback driver needed.

From call to plain files

The queue is just a directory. Anything that can read a file can consume your transcripts.

CaptureMic and system audio on separate branches.
TranscribeOne STT session per branch; local or hosted.
QueueFinished sessions move atomically into sessions/pending/.
Convertonoats convert renders Markdown.

Boring on purpose

Sessions are JSONL, one utterance per line, tagged me or them. The Markdown is rendered from it. Failures are loud and bounded, and a partial session still lands in the queue instead of vanishing.

Session JSONL

{"type":"session_meta","run_id":"…"}
{"type":"utterance","time":…,"text":"Shall we start?","source":"me"}
{"type":"utterance","time":…,"text":"Yes, go ahead.","source":"them"}

Abridged. Full schema in the queue contract.

What you get

A menu-bar app on Apple Silicon, a CLI everywhere.

Menu-bar app

Start, Stop and Flush from the menu bar, with live level meters and STT health.

Your choice of STT

Local Whisper-MLX on Apple Silicon, or a hosted or local WebSocket server such as pipecat-local-stt-server.

Speaker diarization

Opt-in labels (S1, S2…) on the them channel. Off by default, and a failure never loses a transcript.

Fail loud

Capture, STT and storage errors exit non-zero and say why. No silent hangs.

Local-first

Config, queue and transcripts live in your own directories. Process env overrides config files.

Cross-platform CLI

Linux, Windows and Intel Mac use PortAudio capture; native capture needs macOS 14.4+.

Configure once

Pick your microphone, STT service, data directory and privacy options in the app, or run onoats init. The app and CLI read the same config.toml, and a running session keeps the settings it started with.

Install

Apple Silicon with macOS 14.4+ gets the full menu-bar app and native system-audio capture.

macOS 14.4+ — menu bar + native capture

git clone https://github.com/vr000m/onoats-bot.git
cd onoats-bot
make -C native setup

Needs the Xcode Command Line Tools and uv. First run asks for microphone and system-audio permission.

Any platform — CLI + PortAudio

uv tool install onoats
onoats init
onoats bot

System audio on this path needs a loopback device. See the installation guide.
