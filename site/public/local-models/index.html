Run speech models on your Mac

Use the Pipecat Service Toolbar to run local speech-to-text and text-to-speech models on your Mac without a cloud API.

Pipecat Service Toolbar

A native macOS menu-bar app that downloads speech models and serves each one on its own port on 127.0.0.1. Point a Pipecat app at the port and it uses the model. The app has no Dock icon. It stops servers it started when it quits and leaves other servers running.

The toolbar is a separate project from onoats. It lives in the pipecat-local-tts-server repository.

  1. Build and open itNeeds Apple Silicon, macOS 15 or later, Xcode 16+, and uv. Apple Speech needs macOS 26 or later. 
    git clone https://github.com/vr000m/pipecat-local-tts-server.git
cd pipecat-local-tts-server
just app-open
  2. Add a modelClick the cat in the menu bar, choose Add Models, then click Get on a model and Start.
  3. Point your app at itEach running service shows its address, such as 127.0.0.1:9365, with a button to copy it.

Two servers, one pattern

Each server loads one model and listens on a Unix socket or loopback TCP. Both use related event-based WebSocket protocols, but STT and TTS clients remain separate. You can also run the servers without the toolbar.

Speech to text

pipecat-local-stt-server, BSD-2-Clause

  • One WebSocket per transcription session, PCM16 mono at 16 kHz.
  • One final transcript per utterance. Your pipeline supplies voice-activity detection.
  • Unix sockets with a same-user check, or loopback TCP with an optional token.
# in a checkout of the repository
uv sync --extra mlx
uv run --no-sync python -m stt_server serve \
  --backend mlx \
  --socket-path ~/Library/Caches/pipecat-stt/stt.sock

Text to speech

pipecat-local-tts-server, BSD-2-Clause

  • Text in, 16-bit mono PCM out, at the model's true sample rate.
  • Finished segments stream as they are ready, and a cancel message stops speech for barge-in.
  • Unix sockets or loopback TCP. It mirrors the STT server's design, with a protocol inspired by OpenAI Realtime.
uv add "pipecat-local-tts-server[kokoro]"
uv run python -m tts_server prefetch --backend kokoro
uv run python -m tts_server serve --backend kokoro \
  --socket-path ~/Library/Caches/pipecat-tts/tts.sock

Use them with onoats

onoats can send each channel to a local speech-to-text server over WebSocket. With no endpoint set, onoats uses a live legacy cache socket when available; otherwise, it connects to 127.0.0.1:9565, the Whisper port above. To use another model, set its port in config.toml:

[stt]
service = "websocket"
ws_host = "127.0.0.1"
ws_port = 9865

onoats records and transcribes only, so it doesn't use the text-to-speech server. The configuration guide covers sockets, auth, and launchd self-healing.
