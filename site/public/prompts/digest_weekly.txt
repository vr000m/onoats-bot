## Instructions

Produce a weekly digest that synthesises the week's conversations into actionable intelligence. You have two tiers of input per day:

1. **Short daily digest** — always present for every day. Concise, ~800 words, with structured metadata.
2. **Expanded daily digest** — present only for days the system judged high-signal (recurring topics, long discussions, key decisions). These give you full detail.

Your job is to weave these into a coherent weekly narrative. For days where you have only the short summary and the content doesn't warrant depth at the weekly level, a one-line pointer is fine — e.g. "Saturday covered several disparate engineering topics (networking, multimedia, AI); see the daily digest for details."

### Structure

1. **Week overview** — What was the shape of this week? Time breakdown by category. Was it focused or scattered? How does it compare to the previous week?
2. **Major threads** — Topics that spanned multiple days (use the topic recurrence signal above). For recurring themes, synthesise across all days — don't just list each day's contribution separately.
3. **Decisions and commitments** — Key decisions made during the week, with context from expanded dailies where available
4. **Open action items** — All pending items, prioritised
5. **Themes and patterns** — Recurring topics, emerging concerns, things that need attention
6. **Delta vs. last week** — Compare against the previous week's context provided above. Highlight shifts in focus, new themes, resolved issues.
7. **Accomplishments** — What was finished or completed this week. Bullet list, one line each, with `[tid]` citation. Distinguish from in-progress; include only items with clear evidence of completion in the daily input.
8. **Persistent Blockers** — Items unresolved this week that are likely to carry into next week. Bullet list, one line each, with `[tid]` citation and a short reason it persists.

### Constraints
- This should read like a weekly status report that a busy person can scan in 2 minutes.
- Prefer synthesis over enumeration. "SIP debugging was a recurring theme Mon–Wed, culminating in a root cause fix on Wednesday" is better than listing each day's SIP notes.
- For days you have only short summaries for, trust the short summary's assessment of coherence/scatter.
- Write in markdown format.
- Use these level-2 headings verbatim, in this order, for the final three sections: `## Delta vs. last week`, `## Accomplishments`, `## Persistent Blockers`. Downstream parsers depend on exact heading text — do not rephrase, pluralise, or change capitalisation. If a section has no content for the week, emit the heading followed by a single bullet `- _None this week._` so the structure is preserved.
- Do not duplicate items between Accomplishments and Persistent Blockers. A single item belongs in exactly one.
